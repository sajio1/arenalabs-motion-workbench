# SAM runtime acceleration — 2026-10-18

The implementation reuses one video session, text embeddings and a bounded
cache of **raw vision-trunk features** within each SAM worker. Every existing
category and prepared frame is retained. Weights, thresholds, resolution,
source rate (30 Hz), mask rate (15 Hz), bf16 autocast, tracker confirmation and
empty-tracker recovery semantics are unchanged. Finger-contact estimation
was not run.

## Measurements

Hardware: the existing 4 × RTX A6000 48 GB host. Weights were installed; result
caches were cold. Each row is one subprocess run with the same frames,
checkpoint and category list. Worker wall time includes startup, loading,
inference and mask serialization; it is not CUDA kernel time.

| Single-worker comparison | Original | Optimized | Speedup |
|---|---:|---:|---:|
| EgoDex: 266 source frames, 133 prepared frames, 5 categories | 151.19 s | 101.13 s | 1.50× |
| Real robot: 539 source frames, 270 prepared frames, 4 categories | 378.46 s | 302.38 s | 1.25× |

These lists include objects, human foreground, empty categories and tracker
recovery. They do not reproduce production four-way grouping and must not be
substituted directly into a full-job quote.

A separate test used the actual scheduler and four category groups, with a
fresh category cache, for **all 12 categories** in the real-robot recording:

- Retained full-generation baseline: **1,080.21 GPU lease-seconds**.
- Optimized execution: **800.68 GPU lease-seconds**, a **25.88% reduction**.
- New segmentation-stage wall time: **232.92 s**. Each worker queued less than
  one second. Depth, body generation, FOV and packaging are excluded.

The baseline came from the earlier full-generation run with other GPU stages.
Its 433 s wall time contains different queue delays; do not describe 433 →
233 s as controlled inference-only acceleration. GPU leases include CPU/IO
while a card is reserved. These are two clips and one run per configuration,
not a confidence interval or an all-dataset throughput guarantee. The earlier
2–4× estimate was optimistic for these tests.

Raw evidence: [validation/sam-speed-20261018.json](../validation/sam-speed-20261018.json).

## Verification

All five EgoDex and four real-robot categories in matched tests had bit-for-bit
identical uint16 instance masks. All twelve categories in the production-style
test also matched the retained original masks exactly. Source frame indices
and per-frame tracker audits matched. This verifies equivalence to previous
predictions, not ground-truth detection accuracy.

A packaging smoke test compared two categories on 20 prepared frames with the
final frozen worker directory; masks and frame IDs remained exact. Unit tests
cover late detection, empty-tracker restart, complete coverage, bounded memory,
mutating consumers, overlapping batches, changed video identity and cleanup.

## Changes and resource limits

1. `segment_scene.py` starts one video session per worker group. The released
   multiplex `add_prompt` resets tracker state internally, so this caller omits
   redundant external resets. Other recovery-helper callers retain their
   original explicit-reset default. No frames are skipped and no synthetic
   seeds or backward propagation are introduced.
2. `sam_runtime.py` memoizes text-only features for identical captions, device
   and autocast mode. It retains at most 16 entries, returns cloned tensors
   and restores the original method on exit.
3. `sam_features.py` caches the shared vision trunk, before the much larger
   feature pyramids. Per-frame storage shares overlapping prefetch batches.
   Detection, language-conditioned features, tracker memories and masks remain
   fresh. Video identity, tensor shape/stride, device, dtype and autocast mode
   guard reuse. Different batch sizes are not mixed; storage preserves dtype.
4. Cached CPU tensor payload is bounded to **8 GiB per worker** by default,
   or up to 32 GiB across four workers. Video/model state, temporary buffers
   and allocator overhead are additional memory. `ARENA_SAM_IMAGE_CACHE_GIB=0`
   disables trunk caching while retaining the other fixes. Frames that do not
   fit use normal inference. Larger budgets need separate performance checks.
5. Frozen source-job snapshots include the helpers and category coordinator;
   their hashes identify the execution. Coordinator output retains worker
   diagnostics. All dataset adapters continue to use the shared SAM worker.

The model still loads in a new process per GPU worker group. This is not a
globally resident-model service. Four-GPU scheduling, formats, SAM → DA3 point
labeling and downstream FOV stages are retained. Existing valid mask caches
do not need regeneration for an execution-only optimization.

## Rejected experiments

Caching entire feature pyramids on CPU was slower because of copying and
transfer costs; increasing that cache to 32 GiB did not resolve this. Relaxing
batch-shape identity caused pixel differences and was rejected. Isolated
outputs/logs remain private and were not published as production assets.
The final implementation caches only the smaller trunk output and retains
batch shape in its identity. No lower frame rate/resolution, category deletion,
unvalidated compiler mode or first-frame-only discovery was used.

## Reproduce on a configured worker

Use the existing SAM environment/checkpoint and prepared 15 Hz JPEG frames.
Keep experimental output separate from published assets:

```bash
CUDA_VISIBLE_DEVICES=0 \
ARENA_SEGMENT_FRAMES=/private/recording/frames \
ARENA_SEGMENT_OUTPUT=/private/experiment/masks \
ARENA_SEGMENT_PROMPTS='[["object-01","cup"],["human-hand","hand"]]' \
ARENA_SAM_IMAGE_CACHE_GIB=8 \
/path/to/sam-venv/bin/python src/arenalab_workbench/segment_scene.py
```

Choose prompts from source metadata/discovery; the example is not a per-action
production rule. Compare decompressed arrays, frame IDs and tracker audits as
well as timing. For parallel execution use `segment_parallel.py`, an isolated
`ARENA_SCHEDULER_ROOT` and a fresh `ARENA_SAM_CATEGORY_CACHE` directory.
